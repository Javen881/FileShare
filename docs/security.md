# 授权与数据安全设计

## 入口与会话

- 访问令牌使用 `secrets.token_urlsafe(32)`，数据库仅保存 SHA-256 摘要。
- 链接为 `/enter/<token>`，GET 只检查有效性，不消耗授权。URL 在页面加载后被替换为 `/session`。
- PIN 使用带随机盐的 scrypt 哈希；成功登录在 SQLite 事务内删除邀请并建立会话，防止并发重复兑换。
- 共享首页 `/` 始终拒绝；`/session` 和文件接口均由服务端检查会话。
- Cookie 使用 Secure、HttpOnly、SameSite=Strict 和 `__Host-` 前缀；访客和管理员使用不同 cookie、会话表及登录接口。
- 写接口要求正确 Origin；已登录写操作还要求会话 CSRF token。管理员端口与访客端口的 Origin 不能混用。
- 管理会话空闲 30 分钟失效，绝对有效期 8 小时；管理员登录有速率限制。

## 文件处理

- 文件存储名为随机 ID，原文件名和逻辑文件夹均通过数据库关联，拒绝路径分隔符和控制字符。
- 文件使用附件形式下载，不直接执行或预览上传内容，无 Nginx 静态文件直链。
- 上传按数据块写入临时文件，完成后 fsync 并原子移动；失败上传会清理。
- 两个服务共享数据库中的上传配额预留，避免同时上传时只计算各自进程内的配额。
- 访客只能上传、浏览、下载。管理员删除仅标记回收站状态，访客查询与下载立即过滤；恢复保留原目录位置。
- 文件移入回收站不会释放空间。已有网络缓冲和已下载数据不能通过撤销追回。

## 部署与日志

- 后端仅监听回环地址，由 Nginx 提供 HTTPS；管理入口默认只放行内网地址。
- systemd 依赖 `/data` 挂载，使用无特权用户、只读代码和受限写目录。
- Nginx 访问日志会隐藏 `/enter/` 后的令牌，不记录查询参数或 PIN。
- 操作审计在 SQLite 中保存。普通文本日志轮转保留 14 份；数据库审计暂未配置自动保留期限。
- 不应把数据库、运行配置、私钥、上传文件或备份提交到 Git。

## 边界

所有用户共享同一目录树，尚无用户/文件夹级 ACL。管理员和访客后端使用同一系统账户及数据库，独立端口不等于强主机隔离。链接 + PIN 证明凭证持有权，不证明微信身份。未提供病毒扫描、内容审查、断点续传、独立安全审计或自动证书续期。
